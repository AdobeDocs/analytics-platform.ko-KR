# Workspace 프로젝트에서 캐시된 결과 사용

>[!CONTEXTUALHELP]
>id="project_cached_results"
>title="더 빠른 로드를 위해 캐시된 결과 사용"
>abstract="활성화되면 사용자가 프로젝트를 처음 열거나 일정에 의해 전달된 후 12시간 동안 결과가 즉시 로드됩니다. 해당 시간 동안 프로젝트를 여는 모든 사용자는 데이터가 백그라운드에서 계속 전송되더라도 동일한 결과를 볼 수 있습니다. 최신 결과를 로드하려면 개별 패널 또는 전체 프로젝트를 새로 고칩니다."

{{release-limited-testing}}

12시간 동안 캐시된 결과를 표시하도록 Analysis Workspace 프로젝트를 구성할 수 있으므로 프로젝트를 처음 로드한 후 여는 모든 사용자가 결과를 즉시 로드할 수 있습니다.

프로젝트는 처음에 프로젝트를 여는 사용자나 예약된 프로젝트 게재에 의해 로드될 수 있습니다.

## 프로젝트의 캐시된 결과 이해

### 결과가 캐시되는 경우

프로젝트가 처음 로드될 때 결과는 정상 속도로 로드되고 Analysis Workspace은 12시간 동안 캐시됩니다. 이 문제는 다음과 같은 경우에 발생합니다.

* 누군가 프로젝트를 열었습니다.

* 예약된 게재를 위해 프로젝트 실행

예를 들어 프로젝트가 오전 6시에 배달되도록 예약되어 있는 경우 결과는 오후 6시까지 캐시됩니다. 오전 6시에서 오후 6시 사이에 프로젝트를 여는 모든 사용자는 프로젝트를 처음 여는 사람을 포함하여 결과가 즉시 로드됩니다.

12시간 후 캐시된 결과가 만료됩니다. 다음에 프로젝트가 로드되면 사용자가 프로젝트를 열든 예약된 배달을 실행하든 결과는 정상 속도로 로드되고 새 12시간 창이 시작됩니다.

### 캐시된 결과

#### 프로젝트는 원래 구성으로 캐시됩니다

Analysis Workspace은 선택한 데이터 보기, 적용된 세그먼트, 날짜 범위, 패널 드롭다운 선택 사항 등을 사용하여 원래 구성된 대로 프로젝트의 결과를 캐시합니다. 프로젝트를 여는 모든 사용자에게 이러한 캐시된 결과가 표시됩니다.

누군가 캐시된 프로젝트를 보는 동안 프로젝트 구성을 변경하면 결과가 즉시 로드되지 않고 [새 프로젝트 변형이 캐시됩니다](#project-variations-are-cached-as-the-project-is-modified).

#### 프로젝트가 수정되면 프로젝트 변형이 캐시됩니다.

프로젝트의 새 변형은 패널 드롭다운 메뉴에서 항목을 선택하거나, 세그먼트를 적용하거나, 날짜 범위를 변경하거나, 선택한 데이터 보기를 변경하는 등의 작업을 통해 원래 구성을 변경할 때 만들어집니다.

새로운 변형은 처음 정상 속도로 로드됩니다. 그 후에는 그 결과도 캐시되므로 동일한 변형을 로드하는 사람은 누구나 결과를 즉시 볼 수 있습니다.

다음 사항을 고려하십시오.

* Analysis Workspace은 누군가가 로드하는 프로젝트의 각 변형을 캐시합니다. 프로젝트의 가능한 모든 변형을 캐시하지는 않습니다.

* 새 변형을 캐시하는 것은 이미 캐시된 결과를 덮어쓰거나 무효화하지 않습니다. 원래 프로젝트는 사람들이 로드한 다른 변형과 함께 캐시됩니다.

>[!BEGINSHADEBOX]

**예제 시나리오**

글로벌 캠페인 성과 프로젝트에 서로 다른 지역의 세그먼트가 포함되어 있고 오전 6시에 게재되도록 예약되어 있다고 가정해 보십시오.

| 시간 | 작업 | 로드 속도 |
| --- | --- | --- |
| 오전 6:00 | 예약된 프로젝트 게재 | 보통(결과가 나중에 사용하기 위해 캐시됨) |
| 오전 7:06 | 사용자 A가 프로젝트를 엽니다. | 인스턴트 |
| 오전 7:07 | 사용자 A가 아메리카 세그먼트를 적용합니다 | 보통(결과가 나중에 사용하기 위해 캐시됨) |
| 오전 8:01 | 사용자 B가 프로젝트를 엽니다. | 인스턴트 |
| 오전 8:05 | 사용자 B는 아메리카 세그먼트를 적용합니다 | 인스턴트 |
| 오전 8:12 | 사용자 B가 EMEA 세그먼트를 적용합니다 | 보통(결과가 나중에 사용하기 위해 캐시됨) |

>[!ENDSHADEBOX]

### 캐시된 결과가 다음 프로젝트 로드로 새로 고침되도록 하는 변경 사항

프로젝트의 기본 구성을 다음과 같이 변경하면 12시간 기간이 만료되지 않았더라도 다음에 누군가 프로젝트를 열 때 Analysis Workspace이 결과를 새로 고침합니다.

* 차원 또는 지표의 [구성 요소 설정](/help/data-views/component-settings/overview.md) 편집과 같은 데이터 보기의 구성 요소 변경

* [파생 필드](/help/data-views/derived-fields/derived-fields.md)에 대한 변경

* 프로젝트에 사용된 세그먼트 정의 변경 사항

결과가 정상 속도로 로드되고 캐시되어 새 12시간 창이 시작됩니다.

### 캐시된 결과를 보는 사람

캐시된 결과는 다음과 같은 모든 사람에 대해 기본적으로 표시됩니다.

* 프로젝트에 대한 액세스 권한 있음

* 프로젝트에 사용된 데이터 보기에 대한 액세스 권한이 있습니다.

* 동일한 세그먼트 또는 패널 드롭다운 선택이 있는 것과 같이 이미 캐시된 프로젝트의 변형을 로드 중입니다(자세한 내용은 [캐시된 결과 확인](#what-results-are-cached)을 참조하십시오).

캐시된 결과를 볼 때 [수동으로 결과를 새로 고치는](#manually-refresh-results-on-cached-projects)로 최신 데이터를 볼 수 있습니다.

### 프로젝트에서 캐시된 결과를 비활성화하는 경우

일부 프로젝트는 누군가 열 때마다 최신 데이터를 반영하도록 결과에 따라 달라집니다. 이는 자주 업데이트되는 당일 데이터, 늦게 도착하는 데이터 또는 [조회 데이터 세트](/help/getting-started/cja-upgrade/cja-upgrade-dataset-lookup.md)에 많이 의존하는 프로젝트에서 일반적입니다.

프로젝트에 액세스하는 대부분의 사람이 다음을 봐야 하는 경우 프로젝트에서 캐시된 결과를 비활성화하십시오.

* **현재 날짜의 데이터**

  프로젝트가 오전 7시에 캐시되는 경우 캐시된 결과가 오후 7시에 만료되기 전까지 오전 7시 이후에 도착하는 데이터는 결과에 포함되지 않습니다.

* **늦게 도착하는 데이터 즉시**

  늦게 도착하는 데이터에는 이전 기간의 타임스탬프가 있지만 해당 기간이 지난 후에 도착합니다. 예를 들어, 다음 날 콜센터의 [일괄 데이터](/help/data-ingestion/batch.md)를 업로드하거나, 오프라인 상태에서 저장된 이벤트를 모바일 앱에서 전송할 수 있습니다. 캐시된 결과는 만료될 때까지 이 데이터를 포함하지 않습니다.

* **조회 값을 업데이트했습니다**

  캐시된 결과는 만료될 때까지 이전 제품 이름과 같은 이전 조회 값을 계속 표시합니다.

>[!NOTE]
>
>이러한 요구 사항이 가끔 발생하면 캐시된 결과를 사용하도록 설정하고 최신 데이터가 필요할 때 [수동으로 프로젝트를 새로 고치십시오](#manually-refresh-results-on-cached-projects).

## 프로젝트에 대해 캐시된 결과 활성화

프로젝트 설정을 업데이트할 수 있는 누구나 캐시된 결과를 활성화할 수 있습니다. 여기에는 프로젝트 소유자와 프로젝트에 대해 **[!UICONTROL 원본 편집]** 역할을 가진 모든 사람이 포함됩니다. 프로젝트 역할에 대한 자세한 내용은 [특정 프로젝트 역할 공유](/help/analysis-workspace/curate-share/share-projects.md#share-a-specific-project-role)를 참조하십시오.

>[!IMPORTANT]
>
>현재 날짜 데이터, 늦게 도착하는 데이터 또는 업데이트된 조회 값을 즉시 확인해야 하는 경우 캐시된 결과가 적합하지 않을 수 있습니다. 이 설정을 활성화하기 전에 [프로젝트에서 캐시된 결과를 비활성화하는 시기](#when-to-leave-cached-results-disabled-on-a-project)를 검토하십시오.

보다 빠른 로드를 위해 캐시된 결과를 활성화하려는 Workspace 프로젝트에서 다음을 수행합니다.

1. **[!UICONTROL 프로젝트]** > **[!UICONTROL 프로젝트 정보 및 설정]**&#x200B;으로 이동합니다.

1. **[!UICONTROL 더 빠른 로드를 위해 캐시된 결과 사용]**&#x200B;을 선택합니다.

1. **[!UICONTROL 저장]**&#x200B;을 선택합니다.

## 캐시된 결과가 프로젝트에 표시될 때 보기

캐시된 결과가 표시되면 프로젝트 맨 위에 타임스탬프가 표시됩니다. 타임스탬프는 모든 결과가 캐시되는지 또는 일부 결과만 캐시되는지 여부를 지정합니다.

* **[!UICONTROL 결과 표시] [_날짜 및 시간_]**: 프로젝트의 모든 패널에 표시된 날짜 및 시간의 캐시된 결과가 표시됩니다.

* **[!UICONTROL 일부 결과 표시] [_날짜 및 시간_]**: 일부 패널은 표시된 날짜 및 시간의 캐시된 결과를 표시하지만 다른 패널은 최근에 새로 고침되었습니다.

캐시된 프로젝트의 ![타임스탬프](assets/project-cache-timestamp.png)

패널에는 결과가 캐시된 시기를 보여주는 타임스탬프도 표시됩니다.

* **[!UICONTROL 결과 표시] [_날짜 및 시간_]**: 패널에 표시된 날짜 및 시간의 캐시된 결과가 표시됩니다.

  >[!NOTE]
  >
  >이 옵션은 릴리스의 알파 단계 중에는 사용할 수 없습니다.

## 캐시된 프로젝트의 결과를 수동으로 새로 고침

프로젝트에 표시된 결과만 캐시됩니다. 기본 이벤트 데이터는 평소대로 Customer Journey Analytics으로 계속 전송됩니다.

캐시된 결과가 만료되기 전에 최신 데이터를 보려면 12시간 기간 동안 언제든지 프로젝트의 결과를 수동으로 새로 고칠 수 있습니다. 전체 프로젝트를 새로 고치면 새 12시간 창이 시작되고 해당 창 중에 프로젝트를 여는 모든 사용자에게 새로 고친 결과가 표시됩니다.

최신 데이터를 보려는 Workspace 프로젝트에서 전체 프로젝트 또는 단일 패널에 대한 결과를 새로 고칠 수 있습니다.

### 전체 프로젝트에 대한 결과 새로 고침

모든 패널에 대한 최신 결과를 로드하고 새 12시간 창을 시작하려면 다음을 수행하십시오.

1. 프로젝트 타임스탬프 옆에 있는 프로젝트 맨 위에서 **[!UICONTROL 새로 고침]** ![새로 고침](/help/assets/icons/Refresh.svg) 아이콘을 선택합니다.

### 단일 패널에 대한 결과 새로 고침

>[!NOTE]
>
>이 옵션은 릴리스의 알파 단계 중에는 사용할 수 없습니다.

단일 패널에 대해서만 최신 결과를 로드하려면 다음을 수행합니다.

1. 패널의 타임스탬프 옆에 있는 **[!UICONTROL 새로 고침]** ![새로 고침](/help/assets/icons/Refresh.svg) 아이콘을 선택합니다.
