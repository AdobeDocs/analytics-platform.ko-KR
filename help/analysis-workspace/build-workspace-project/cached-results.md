# Workspace 프로젝트에서 캐시된 결과 사용

>[!CONTEXTUALHELP]
>id="project_cached_results"
>title="더 빠른 로드를 위해 캐시된 결과 사용"
>abstract="활성화되면 사용자가 프로젝트를 처음 열거나 일정에 의해 전달된 후 12시간 동안 결과가 즉시 로드됩니다. 해당 시간 동안 프로젝트를 여는 모든 사용자는 데이터가 백그라운드에서 계속 전송되더라도 동일한 결과를 볼 수 있습니다. 최신 결과를 로드하려면 개별 패널 또는 전체 프로젝트를 새로 고칩니다."

12시간 동안 캐시된 결과를 표시하도록 Analysis Workspace 프로젝트를 구성할 수 있으므로 프로젝트를 처음 로드한 후 여는 모든 사용자가 결과를 즉시 로드할 수 있습니다.

프로젝트는 처음에 프로젝트를 여는 사용자나 예약된 프로젝트 게재에 의해 로드될 수 있습니다.

>[!NOTE]
>
>쿼리 결과만 캐시됩니다. 기본 이벤트 데이터는 평소대로 Customer Journey Analytics으로 계속 전송됩니다.
>
>캐시된 결과가 만료되기 전에 최신 데이터를 보려면 [결과를 수동으로 새로 고치십시오](#manually-refresh-results-on-cached-projects).

## 프로젝트의 캐시된 결과 이해

### 결과가 캐시되는 경우

프로젝트가 처음 실행될 때 Analysis Workspace은 평소대로 쿼리를 실행하고 12시간 동안 결과를 캐시합니다. 이 문제는 누군가가 프로젝트를 열거나 프로젝트가 예약된 게재에 대해 실행될 때 발생합니다. 예를 들어 프로젝트가 오전 6시에 배달되도록 예약되어 있는 경우 결과는 오후 6시까지 캐시됩니다. 오전 6시에서 오후 6시 사이에 프로젝트를 여는 모든 사용자는 프로젝트를 처음 여는 사람을 포함하여 결과가 즉시 로드됩니다.

12시간 후 캐시된 결과가 만료됩니다. 사용자가 프로젝트를 열지 또는 예약된 배달이 실행되는지 여부에 관계없이 프로젝트에 대한 다음 쿼리는 일반 속도로 로드되고 새 12시간 창이 시작됩니다.

### 캐시된 결과

Analysis Workspace은 가능한 모든 프로젝트 버전이 아니라 실행되는 각 쿼리를 캐시합니다.

패널 드롭다운 메뉴에서 항목을 선택하거나 세그먼트를 적용하는 등 프로젝트에서 쿼리를 변경하면 Analysis Workspace에서 새 쿼리를 실행합니다. 새 쿼리는 처음 일반 속도로 로드됩니다. 그 후에는 그 결과도 캐시되므로 동일한 쿼리를 실행하는 사람은 즉시 결과를 볼 수 있습니다.

새 쿼리를 캐시하는 것은 이미 캐시된 결과를 덮어쓰거나 무효화하지 않습니다. 원래 프로젝트 보기는 사용자가 실행한 다른 변형과 함께 캐시됩니다.

>[!BEGINSHADEBOX]

**예제 시나리오**

글로벌 캠페인 성과 프로젝트에 서로 다른 지역의 세그먼트가 포함되어 있고 오전 6시에 게재되도록 예약되어 있다고 가정해 보십시오.

| 시간 | 작업 | 로드 속도 |
| --- | --- | --- |
| 오전 6:00 | 예약된 프로젝트 게재 | 보통(결과가 나중에 사용하기 위해 캐시됨) |
| 오전 7:06 | 사용자 A가 프로젝트를 엽니다. | 인스턴트 |
| 오전 7:06 | 사용자 A가 아메리카 세그먼트를 적용합니다 | 보통(결과가 나중에 사용하기 위해 캐시됨) |
| 오전 8:01 | 사용자 B가 프로젝트를 엽니다. | 인스턴트 |
| 오전 8:01 | 사용자 B는 아메리카 세그먼트를 적용합니다 | 인스턴트 |
| 오전 8:01 | 사용자 B가 EMEA 세그먼트를 적용합니다 | 보통(결과가 나중에 사용하기 위해 캐시됨) |

>[!ENDSHADEBOX]

### 캐시된 결과를 보는 사람

캐시된 결과는 다음과 같은 모든 사람에 대해 기본적으로 표시됩니다.

* 프로젝트에 대한 액세스 권한 있음

* 프로젝트에 사용된 데이터 보기에 대한 액세스 권한이 있습니다.

* 는 이전에 캐시된 것과 동일한 쿼리 매개 변수를 프로젝트에서 사용하고 있습니다(예: 보고 있는 프로젝트가 이전에 캐시된 프로젝트와 동일한 세그먼트 또는 패널 드롭다운 선택 사항을 사용함).

캐시된 결과를 볼 때 [수동으로 결과를 새로 고치는](#manually-refresh-results-on-cached-projects)로 최신 데이터를 볼 수 있습니다.

## 프로젝트에 대해 캐시된 결과 활성화

프로젝트 설정을 업데이트할 수 있는 누구나 캐시된 결과를 활성화할 수 있습니다. 여기에는 프로젝트 소유자와 프로젝트에 대해 **[!UICONTROL 원본 편집]** 역할을 가진 모든 사람이 포함됩니다. 프로젝트 역할에 대한 자세한 내용은 [특정 프로젝트 역할 공유](/help/analysis-workspace/curate-share/share-projects.md#share-a-specific-project-role)를 참조하십시오.

거의 즉시 로드할 수 있도록 캐시된 결과를 활성화하려는 Workspace 프로젝트에서

1. **[!UICONTROL 프로젝트]** > **[!UICONTROL 프로젝트 정보 및 설정]**&#x200B;으로 이동합니다.
1. **[!UICONTROL 더 빠른 로드를 위해 캐시된 결과 사용]**&#x200B;을 선택합니다.
1. **[!UICONTROL 저장]**&#x200B;을 선택합니다.

## 캐시된 결과가 프로젝트에 표시될 때 보기

캐시된 결과가 표시되면 프로젝트 맨 위에 타임스탬프가 표시됩니다. 타임스탬프는 모든 결과가 캐시되는지 또는 일부 결과만 캐시되는지 여부를 지정합니다.

* **[!UICONTROL 결과 표시] [_날짜 및 시간_]**: 프로젝트의 모든 패널에 표시된 날짜 및 시간의 캐시된 결과가 표시됩니다.
* **[!UICONTROL 일부 결과 표시] [_날짜 및 시간_]**: 일부 패널은 표시된 날짜 및 시간의 캐시된 결과를 표시하지만 다른 패널은 최근에 새로 고침되었습니다.

캐시된 프로젝트의 ![타임스탬프](assets/project-cache-timestamp.png)

패널에는 결과가 캐시된 시기를 보여주는 타임스탬프도 표시됩니다.

* **[!UICONTROL 결과 표시] [_날짜 및 시간_]**: 패널에 표시된 날짜 및 시간의 캐시된 결과가 표시됩니다.

  >[!NOTE]
  >
  >이 옵션은 릴리스의 알파 단계 중에는 사용할 수 없습니다.

## 캐시된 프로젝트의 결과를 수동으로 새로 고침

12시간 기간 동안 언제든지 프로젝트의 결과를 수동으로 새로 고쳐 최신 데이터를 볼 수 있습니다. 전체 프로젝트를 새로 고치면 새 12시간 창이 시작되고 해당 창 중에 프로젝트를 여는 모든 사용자에게 새로 고친 결과가 표시됩니다.

최신 데이터를 보려는 Workspace 프로젝트에서 전체 프로젝트 또는 단일 패널에 대한 결과를 새로 고칠 수 있습니다.

### 전체 프로젝트에 대한 결과 새로 고침

모든 패널에 대한 최신 결과를 로드하고 새 12시간 창을 시작하려면 다음을 수행하십시오.

1. 프로젝트 타임스탬프 옆에 있는 프로젝트 맨 위에서 **[!UICONTROL 새로 고침]** ![새로 고침](/help/assets/icons/Refresh.svg) 아이콘을 선택합니다.

### 단일 패널에 대한 결과 새로 고침

>[!NOTE]
>
>이 옵션은 릴리스의 알파 단계 중에는 사용할 수 없습니다.

단일 패널에 대해서만 최신 결과를 로드하려면 다음을 수행합니다.

1. 패널 타임스탬프 옆에 있는 프로젝트 맨 위에서 **[!UICONTROL 새로 고침]** ![새로 고침](/help/assets/icons/Refresh.svg) 아이콘을 선택합니다.
